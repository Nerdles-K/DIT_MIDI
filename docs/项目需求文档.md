# 项目需求文档

**项目:** Text-to-MIDI 音乐生成系统  
**版本:** 2.0 | **日期:** 2025-11-28  
**数据集:** BabySlakh

---

## 1. 项目概述

基于 DiT 和 AdaLN-Zero 的文本驱动 MIDI 生成系统。

**示例:** `"happy piano melody in C"` → MIDI 文件

**技术栈:**
- DiT 架构（Transformer 替代 U-Net）
- AdaLN-Zero（零初始化提升稳定性）
- 文本条件生成
- 自动特征提取

---

## 2. 功能需求

**F1: 文本到 MIDI**
- 格式: `{乐器} {强度} {情绪} melody in {调性}`
- 输出: MIDI 文件（5-30秒，50步<10秒）

**F2: 批量生成** - 文本列表 → 多个 MIDI

**F3: 模型训练** - 特征提取 → 训练 → 保存检查点

**可配置:** 采样步数、温度、时长、BPM、力度

---

## 3. 数据需求

**数据集:**
- 格式: MIDI (.mid)，多轨多乐器
- 数量: 测试 10+，训练 100-1000+
- 时长: 10-60秒，音符数 ≥10

**预处理:**
1. MIDI 清洗 → 提取有效轨道
2. Piano Roll 矩阵化 (T×P，T=时间轴 1/16音符，P=[21,108])
3. Patchify → 16×16 Patch
4. 特征提取 → 乐器(14种)、速度(5级)、调性(12音)、情绪(4种)

**文本格式:** `{乐器} {强度} {情绪} melody in {调性}`

**缓存:** 首次加载特征存至 `.cache/text_features.json`

---

## 4. 模型架构

```
文本 → 编码器(768维) → 条件嵌入
                         ↓
噪声Patches → DiT ←────┘ → 去噪 → Piano Roll → MIDI
```

**TextEncoder:** 4层Transformer，768维，8头，56词汇，~29M参数

**DiT:** Patch 256维(16×16)，768维嵌入，12层Block，12头，序列长2048，~96M参数

**AdaLN-Zero:** $\text{AdaLN}(x, c) = (1 + \gamma(c)) \cdot \text{LN}(x) + \beta(c)$  
条件 $c = [\text{timestep}, \text{class}, \text{text}]$，零初始化

---

## 5. 训练需求

**配置:** PyTorch+Lightning, DDPM, MSE Loss, AdamW, LR=1e-4(Warmup 1000), BS=8, FP16, 100 Epoch, 梯度裁剪1.0

**流程:**
1. 批次 `(patches, text, masks)`
2. 编码 `text_emb = encoder(text)`
3. 加噪 `noisy = clean + σ(t)·ε`
4. 预测 `pred_ε = model(noisy, σ(t), text_emb)`
5. 损失 `MSE(pred_ε, ε)`
6. 反向传播

**保存:** Top-3验证损失 + 最后epoch，早停10轮

---

## 6. 推理需求

**DDPM采样:** 初始噪声 → 编码文本 → 迭代去噪T步 → Unpatchify → MIDI

**参数:** num-steps(50,25-250), temperature(1.0,0.5-2.0), duration(10s,5-30), tempo(120,60-180), velocity(80,40-127)

---

## 7. 评估指标

**客观:** MSE Loss, Empty Bar Rate(<0.1), Pitch KL散度(<0.5), Duration Entropy(>2.0)

**主观:** 旋律连贯性、节奏稳定性、情绪匹配度

---

## 8. 系统需求

**硬件:** 最低 GTX 1660(6GB)+16GB RAM, 推荐 RTX 4060(8GB)+32GB RAM

**软件:** Python 3.8+, PyTorch 2.0+(CUDA 11.8+), Lightning 2.0+, pretty-midi, Hydra

## 10. 约束与风险

**约束:** 单轨生成、时长≤30秒、固定文本格式、需6GB+显存、训练8-24小时

**风险对策:** 内存不足→减BS/梯度累积，不收敛→调LR/检查数据，质量差→增数据/延长训练
