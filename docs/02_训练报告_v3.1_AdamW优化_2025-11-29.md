4. **验证集偏小** (10%) → val_loss波动较大

1. 降低学习率至6e-5 (-25%)
2. 增加patience至15 (+87.5%)
3. 延长warmup至3000步 (+50%)
4. 增加验证集至15% (+50%)
5. 使用梯度累积模拟更大batch (等效BS=24)
6. 降低dropout至0.12,提升模型容量

## 七、经验总结与最佳实践

### 7.1 关键经验

#### 1. Early Stopping Patience的设置原则

**经验公式:**
```
patience = data_size_factor × model_size_factor × base_patience

其中:
- base_patience = 5 (小数据集基准)
- data_size_factor = log10(num_files / 100)
- model_size_factor = sqrt(params_M / 50)

示例:
- 20文件, 96M: patience = 1.0 × 1.4 × 5 ≈ 7
- 500文件, 67.8M: patience = 1.7 × 1.2 × 5 ≈ 10
- 1000文件, 125M: patience = 2.0 × 1.6 × 5 ≈ 16 ✅
```

**本次实验验证:**
- v3.0: patience=8 → 10 epochs停止 ❌ 太早
- v3.1: patience=15 → 33 epochs停止 ✅ 合适

#### 2. 学习率与模型规模的关系

**经验规则:**
```
lr = base_lr × sqrt(batch_size / 16) / sqrt(params_M / 100)

对于本实验:
- base_lr = 1e-4 (标准基准)
- effective_batch_size = 24 (12 × 2 accumulation)
- params = 125M

计算: lr = 1e-4 × sqrt(24/16) / sqrt(125/100)
        = 1e-4 × 1.22 / 1.12
        ≈ 1.09e-4

但考虑稳定性,使用6e-5 ✅
```

**验证:**
- 8e-5 (v3.0): 过高 → 震荡
- 6e-5 (v3.1): 合适 → 平稳收敛 ✅

#### 3. 数据量与模型规模的平衡

**经验比率:**
```
params_per_sample = total_params / num_samples

安全阈值: 10K - 100K params/sample

本实验:
- v1.0: 96M / 20 = 4.8M params/sample ❌ 严重过拟合
- v2.0: 67.8M / 500 = 136K params/sample 🟡 轻微过拟合
- v3.1: 125M / 1000 = 125K params/sample ✅ 平衡良好
```

#### 4. 梯度累积的有效性

**本次验证:**
```
配置: batch_size=12, accumulate_grad_batches=2
等效: batch_size=24

优势:
- ✅ 显存占用不变 (~7.2GB)
- ✅ 梯度估计更准确
- ✅ 训练更稳定
- 🟡 时间增加可忽略 (~3%)
```
